Pickle Rick — Room Walkthrough

Pickle Rick is a Rick and Morty-themed TryHackMe challenge where Rick has turned himself into a pickle and needs three secret ingredients to brew a potion that turns him back into a human. Compromising the target involves web source enumeration, directory brute-forcing, exploiting an authenticated web command panel, bypassing blacklisted commands, and abusing passwordless sudo privileges.

Opening the browser developer tools (Inspect / View Source) uncovered a developer comment hidden in the HTML containing a valid username:

<!--

I saved R1ckRul3s in a text editor for later use. Since no other clues appeared in the page source, I launched gobuster using the directory-list-2.3-medium.txt wordlist—a balanced wordlist ideal for thorough web enumeration—along with common web extensions (php, html, js, txt):

Inspecting the discovered endpoints revealed two critical pieces of information:

  • /robots.txt contained a single weird string: Wubbalubbadubdub, which I saved alongside the username as a potential password.
  • /assets/ contained static media files with nothing useful, while /portal.php redirected directly to the authentication form at /login.php.

02. Initial Access & First Ingredient

Navigating to http://10.113.145.39/login.php, I tested the credentials gathered during enumeration: R1ckRul3s as the username and Wubbalubbadubdub as the password. The login succeeded and granted access to portal.php, which exposed a web-based Command Panel capable of executing OS commands directly on the server.

To verify execution context and enumerate the web root, I ran whoami, pwd, and ls inside the command input field:

$ whoami

$ pwd

$ ls

Two interesting text files appeared in /var/www/html: Sup3rS3cretPickl3Ingred.txt and clue.txt. Since both files resided inside the public web directory, I accessed them directly through the browser to retrieve the first ingredient and the next hint:

# http://10.113.145.39/Sup3rS3cretPickl3Ingred.txt

04. Privilege Escalation & Third Ingredient

With /root inaccessible to the standard www-data user, I checked the account's sudo privileges using sudo -l to look for privilege escalation paths:

$ sudo -l
Matching Defaults entries for www-data on ip-10-113-152-251:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin

User www-data may run the following commands on ip-10-113-152-251:
    (ALL) NOPASSWD: ALL
